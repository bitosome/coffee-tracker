# Implementation contract, v0.1.0

One config entry per shared pool. Config flow: name (Coffee pool), currency (EUR, supported two-decimal ISO currencies), cup_price (2.00), opening_balance (0.00). Negative balances allowed: this is consumption tracking, not payment authorization; warn and invite a top-up. Price must be positive. Ledger integer cents, timestamps UTC, durable before success, per-pool async lock. Storage failure leaves state unchanged. Persistent idempotency keys protect retried requests. Changing price affects future coffees only.

Entities: sensor.<pool>_balance, sensor.<pool>_coffees (lifetime net count); number.<pool>_cup_price (0.01..10000, step .01); button.<pool>_buy_coffee.
Balance attributes: integration: coffee_tracker; pool_id: config entry ID; currency; cup_price_minor; balance_minor; revision; coffee_count; last_action_at; price_entity_id; coffee_button_entity_id (discover actual registry IDs, not guessed). State is decimal major currency unit; no transaction history in recorder attributes.

All domain services use required entity_id of the balance sensor. Mutation services optional request_id (string 8..128). set_balance/set_price/undo require expected_revision (integer). buy_coffee may take expected_revision so stale card price can be rejected; button presses use current price atomically. add_funds amount positive major decimal. set_balance amount signed absolute major decimal plus optional note. set_price amount positive major decimal. buy_coffee no amount. undo transaction_id of latest financial transaction only; append compensating history, never delete. get_history limit 1..100 default20, before optional sequence integer, returns {items, has_more, next_before, revision}. Financial mutations return {balance_minor,cup_price_minor,coffee_count,currency,revision,transaction_id}; support response optional. Each history item: id (UUID), sequence, kind (opening_balance/add_funds/buy_coffee/set_balance/set_price/undo), amount_minor (signed balance delta), balance_minor, cup_price_minor, coffee_count, timestamp (UTC ISO), actor (HA user name or Automation), note, undo_of (optional), undoable (computed for latest eligible entry). Currency fixed for lifetime of ledger. Undo only latest financial entry and cannot undo an undo; restores count for coffee.

UI config: type custom:coffee-tracker-card, entity required balance sensor, title optional. Discover stub only marked coffee_tracker balance sensor. Main view shows balance, cups available (floor max(balance,0)/price), price chip; Coffee purchased primary button; Add money, adjust balance/settings compact tools; persisted history with load more, optional Undo latest explicit action. Animation only after service success. Shared updates use hass sensor revision; no optimistic double charge. Use hass.callService(domain, service, data, undefined, false, true) for response calls (or callWS type call_service return_response true), read service response envelope appropriately. Refresh history on revision change. Editor must list only marked balance sensors. Mock preview no real HA connections.

Owner work areas: backend agent custom_components/**/*.py,json,yaml except www; backend tests tests/. Frontend agent src/, test/, preview/, package.json/lock, tsconfig/rollup.
